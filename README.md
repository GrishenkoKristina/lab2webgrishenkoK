# Панель Кристины — интерактивная панель управления UI-компонентами

## Тема и назначение
«Панель путешественника» — адаптивный веб-дашборд, в котором пользователь собирает собственную панель из отдельных виджетов. Оформление выполнено в белом, красном и чёрном цветах.

## Технологии
HTML5, CSS3, обычный JavaScript (без React, npm и сборки), ES-модули, классы, Fetch API и localStorage.

## Запуск в Visual Studio Code
1. Распакуйте архив.
2. В Visual Studio Code выберите **Файл → Открыть папку** и укажите папку `panel_puteshestvennika`.
3. Установите расширение **Live Server**, если оно ещё не установлено.
4. Откройте `index.html`, нажмите правой кнопкой мыши и выберите **Open with Live Server**.
5. Для загрузки погоды и курса валют требуется подключение к интернету. Для запуска ES-модулей можно использовать любой локальный статический сервер.

Не открывайте HTML двойным щелчком: для корректной работы ES-модулей используйте локальный сервер.

## Реализованные виджеты
- **Мои планы** — добавление непустых задач, отметка выполнения, удаление, счётчик и индикатор прогресса подготовки.
- **Погода** — текущая температура, описание условий, ощущаемая температура, влажность, ветер и прогноз на 3 дня. Можно выбрать Владивосток, Москву, Санкт-Петербург, Берлин или Токио.
- **Конвертер валют** — актуальный курс EUR/USD, дата публикации и пересчёт введённой суммы в реальном времени.

## Управление панелью
- Добавление трёх типов виджетов через список и кнопку.
- Запрет повторного добавления одного типа с понятным сообщением.
- Сворачивание и разворачивание карточек.
- Удаление карточки.
- Независимая загрузка данных погоды и валют: ошибка одной карточки не останавливает другую.
- Сетевые карточки показывают загрузку, сообщение об ошибке и кнопку «Повторить».
- Запросы погоды и валют отменяются при удалении соответствующей карточки.

## Внешние API
1. **Open-Meteo** — погода: https://open-meteo.com/en/docs  
   Запрос использует endpoint `/v1/forecast` и параметры `latitude`, `longitude`, `current`, `daily`, `forecast_days`, `timezone`. Ключ API не требуется.
2. **Frankfurter** — курсы валют: https://frankfurter.dev/  
   Запрос: `https://api.frankfurter.dev/v2/rate/eur/usd`. Используется поле `rate` и дата `date`. Конвертация суммы выполняется в браузере по полученному курсу.

Секретные ключи в проекте не используются. Если API временно недоступен, приложение показывает ошибку, а не подставляет вымышленные актуальные значения.

## Структура проекта
- `index.html` — разметка страницы.
- `styles.css` — оформление и адаптация для мобильных экранов.
- `js/UIComponent.js` — базовый класс карточки, кнопки управления и метод `destroy()`.
- `js/ToDoWidget.js` — виджет списка дел.
- `js/WeatherWidget.js` — виджет погоды.
- `js/CurrencyWidget.js` — виджет валют.
- `js/Dashboard.js` — класс управления виджетами, добавление, удаление, восстановление и сохранение.
- `js/main.js` — запуск приложения и связь кнопки с панелью.

## Сохранение данных
Набор виджетов, задачи, выбранный город и сумма для конвертации сохраняются в `localStorage`. После обновления страницы виджеты и задачи восстанавливаются, а погода и курс валют запрашиваются заново. Обработка повреждённого JSON и недоступного `localStorage` предусмотрена.

## Нейросеть и примеры полезных промптов
При разработке использовался ChatGPT для подготовки и проверки структуры HTML, CSS и JavaScript.

**Промпт 1 — базовый класс виджета:**
> Создай на JavaScript класс UIComponent для карточки дашборда. Конструктор принимает id и title. Метод render() создаёт карточку с кнопками сворачивания и удаления, а destroy() удаляет карточку и отменяет связанные запросы. Используй ES-модули и выдай полный код файла.

**Промпт 2 — список дел:**
> Создай класс ToDoWidget, наследующий UIComponent. Добавь поле ввода, кнопку добавления, список задач, отметку выполнения и удаление. Пустые задачи не добавляй, текст выводи через textContent. Сохраняй задачи в свойстве экземпляра.

**Промпт 3 — подключение API и ошибки:**
> Создай независимые виджеты погоды Open-Meteo и курса EUR/USD Frankfurter. Используй fetch и проверку response.ok. Показывай состояние загрузки, реальные данные, ошибку и кнопку повтора. Не подставляй демонстрационные значения вместо актуальных данных. При удалении карточки отменяй запрос через AbortController.

## Чек-лист проверки перед сдачей
1. Добавить все три виджета и убедиться, что повторное добавление типа запрещено.
2. Свернуть и развернуть каждую карточку.
3. Добавить задачу, отметить её выполненной, удалить задачу.
4. Обновить страницу и проверить восстановление виджетов и задач.
5. Проверить погоду и валюты при подключённом интернете.
6. Отключить интернет, перезагрузить сетевые карточки и проверить сообщение об ошибке и кнопку «Повторить».
7. Пять раз удалить и заново добавить каждый виджет. Убедиться, что одно нажатие выполняет одно действие.
8. Проверить отображение на узком экране телефона.

## Публикация и сдача
Для сдачи по заданию нужно отдельно опубликовать сайт и отправить ссылку на сайт и ссылку на репозиторий. Это требует входа в ваш GitHub-аккаунт:
1. Создайте репозиторий GitHub и загрузите в него все файлы проекта.
2. В настройках репозитория откройте **Pages**, выберите публикацию из ветки `main` и папки `/(root)` (если файлы находятся в корне репозитория).
3. Дождитесь публикации и скопируйте ссылку сайта из раздела Pages.
4. В отчёт/преподавателю отправьте обе ссылки: на опубликованный сайт и на репозиторий.

**Важно:** файлы проекта подготовлены, но публикация в вашем GitHub-аккаунте ещё не выполнена. Перед сдачей проверьте доступность обоих API из своей сети.
